確認しました — 分布がほぼ stay（0）に偏っている原因と対策を優先順でまとめます。

要約（現状）
- action distribution: {0:57, 5:1, 6:1, 1:1} → モデルはほぼ常に `action_idx==0`（待機）を選択。`queue_action` は True なので「予約失敗」が原因ではなく、ポリシーが stay を安全策と判断している。

考えられる主要因（優先度高）
1. 観測がユニット固有情報を含まないためポリシーが「どのユニットか」を識別できず、安全な一手（stay）を常に選ぶ。  
   - 現在の obs は4体味方＋4体敵の位置のみ（`current_unit_idx` を入れていない）。
2. 報酬信号が希薄かつペナルティが強い（移動失敗で即 -1、成功報酬は稀） → リスク回避でstay固定化。  
3. 観測が int のまま（np.int32）で正規化されていないため学習が不安定 / 局所解に陥りやすい。  
4. 探索不足（entropy係数が低い等）で確率的多様性が出ない。  
5. （可能性低）行動マッピングに偏りがあり 0 が常に「最も安全」になっている。

優先で試すべき短期対策（すぐ試せる）
1. `current_unit_idx` を観測に追加（即効性が高い）  
   - `_get_obs()` に現在の `self.rust_env.current_unit_idx`（正規化して）を追加し、`observation_space` を拡張。  
   - 期待効果：ユニットごとの方策を学べるようになり、stay偏重が改善される可能性大。  
2. 観測を float に正規化する（例: /35.0）と dtype=np.float32 に変更。  
3. 学習時に探索を増やす：PPO の `ent_coef` を上げる（例 `ent_coef=0.01` → `0.02` など）で多様な行動を促す。  
4. 一時的に stay に小さな負報酬（例 -0.01）または移動に微小正報酬（例 +0.01）を与えて探索を促す（慎重に実験）。  
5. 行動マスク／無効行動の抑止：環境側で無効アクション（盤外・遠すぎ）を弾くか、invalid に対しては小さな負報酬ではなくマスクして選択肢に入れない実装にする。
