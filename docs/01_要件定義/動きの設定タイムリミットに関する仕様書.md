# 動きの設定タイムリミット機能に関する仕様書

## 仕様の詳細

* 「動きの設定」は150秒間で完了すること
  * 150秒経過後に「動きの設定」情報によって戦闘結果の計算が開始される
* 「ユニットの行動」は15秒間で完了すること
  * 15秒経過後に「ユニットの行動」が完了し、次のターンの「動きの設定」が開始される
* 1試合は6ターンで終了すること
* タイマーは両プレイヤーに対して同時に開始される
* タイマーの残り時間は両プレイヤーに表示されること
* タイマーが0になった場合、行動力にあまりがあるユニットに対しては待機行動で埋める

## 参考にした原作セリフ

* 対戦する部隊は
* お互い150秒間ですべてのユニットの動きを設定し
* その後の15秒間ですべてのユニットが行動します
* この「動きの設定」と「ユニットの行動」を1ターンとして
* 1試合は6ターンで終了

## 現実装からの変更案メモ

### 2026-04-18

* タイマーを契機とすると、両プレイヤーの設定が完了しているのにタイマーの動作まで待機しなくてはならない。
* **タイマーは締切**として機能させ、両プレイヤーの設定が完了した段階でターン情報をマージしてユニットの行動結果を算出するのが自然と考えられる。

#### 動きの設定の提出時間を返したほうが良い既存メッセージ

* ゲーム情報取得
* マッチング
* 戦闘計算

ゲーム情報取得時にも動きの設定の提出時間を返す必要がある
-> ゲームリポジトリに登録が必要

#### EventBridge Schedulerの動かし方について

EventBridge Scheduler は各ターンの締切時刻に既存の Lambda を直接起動するようにする。
