### 背景・課題

単純 getter/enum 判定のみのテストが多く混在しており、重要仕様を保護するテスト密度が薄い。
また `step_test.rs` のような空ファイルも残っている。

### 提案内容

1. 削除対象テストを一覧化し、理由を明記したうえで削除する（例: `action_type_test.rs` の単純判定テスト）
2. 以下の仕様テストを追加する
   - ターン解決シナリオ（同時行動・AP 境界・再提出拒否）
   - 視界判定の境界条件（初期配置 / 移動直後 / ターン跨ぎ）
   - 視界外ユニットへの攻撃禁止
3. 空テストファイルを削除または有効化する

### 期待される効果

テスト実行時間と保守コストを抑えつつ、主要仕様の回帰検知力を向上させる。

### 対象範囲

game_server

### 受け入れ条件

- [ ] 削除対象テストの理由が PR 内またはコメントで明記されている
- [ ] ターン解決・視界・攻撃制約の仕様テストが追加されている
- [ ] 空テストファイルが整理されている
